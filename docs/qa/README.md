# اختبار النظام

## التشغيل المحلي ببيانات وهمية

```
npm run local
```

افتح `http://localhost:5180`. السيستم كله بيشتغل على جهازك على داتابيز مؤقتة فيها كل المايجريشن، ومش بيلمس الموقع الحقيقي. البيانات بتتعمل من جديد مع كل تشغيل، وبتتمسح لما تقفله.

| الحساب | كلمة السر | فيه إيه |
|---|---|---|
| `clinic@local.test` | `Local12345` | عيادة بفرعين، ومواعيد قديمة وجاية، وخطة علاج، وملف طبي، وكشف حساب |
| `salon@local.test` | `Local12345` | صالون بـ3 كراسي |
| `expired@local.test` | `Local12345` | حساب تجربته خلصت |

- **صفحات الحجز:** `/book/demo-clinic` و`/book/demo-salon`
- **الأدمن:** `/admin`، وكلمة السر `local-admin-password`

**مش شغال محليًا:** التحديث اللحظي للحجوزات (Realtime)، والدخول بـGoogle، والإيميلات.

## الاختبارات

| الأمر | بيختبر إيه | الوقت |
|---|---|---|
| `npm test` | المنطق (الأرقام والرسايل والمواعيد)، والداتابيز على Postgres حقيقي بكل المايجريشن | دقايق |
| `npm run test:qa` | كل شاشة في متصفح حقيقي: السيناريوهات، والزاحف اللي بيضغط كل زرار | حوالي 45 دقيقة |
| `npm run test:qa -- --grep-invert "every button"` | السيناريوهات من غير الزاحف | حوالي 5 دقايق |
| `npm run test:qa -- --project=iphone --project=android` | الشاشات على موبايل: آيفون (محرك Safari) وأندرويد | دقيقة |
| `npm run check:live` | الداتابيز الحقيقية فيها كل جدول وعمود وعلاقة ودالة الكود بيستخدمها. بقراءة بس بالمفتاح العام، ومن غير ما يرجع ولا صف. شغّله بعد أي مايجريشن | دقيقة |
| `npm run lint` | فحص الكود | ثواني |

- **تقرير الزاحف** بيتكتب في `test-results/crawl-report.json`، وفيه نتيجة كل زرار: `ok` (شغال) و`dead` (ما حصلش حاجة) و`broken` (حصل خطأ).
- **الأخطاء اللي اتلقت** في [bugs.md](bugs.md).

**ميزة جديدة؟** ضيف بياناتها في `tests/local-backend/seed.mjs`، واختباراتها في `tests/qa`.

## بعد الدمج: تنفيذ المايجريشن 043

من غيره زرار "مكتمل" هيفضل يفشل لأي موعد له سعر.

1. افتح Supabase، وبعدين المشروع، وبعدين **SQL Editor**، واعمل **New query**.
2. انسخ محتوى `supabase/migrations/043_fix_completion_and_plan_sync.sql` كله والصقه.
3. اضغط **Run**. المفروض يظهر `Success. No rows returned`.
4. جرّب على الموقع: افتح أي موعد له سعر، واختار "مكتمل"، واضغط حفظ. المفروض يتحفظ، ويظهر في كشف حساب العميل.
5. **لو حصلت مشكلة:** نفّذ `supabase/rollbacks/043_fix_completion_and_plan_sync_down.sql` بنفس الطريقة، وهيرجع زي ما كان.

المايجريشن بيعدّل دالتين بس، ومش بيلمس أي جدول أو بيانات.

## اختبار يدوي على الموقع بعد الدمج

حاجات ما ينفعش تتختبر محليًا. كل واحدة بتاخد دقيقة:

- [ ] **الدخول بـGoogle** بحساب جديد: المفروض يسأل عن رقم الواتساب، وبعدين يفتح الإعداد الأولي.
- [ ] **نسيت كلمة المرور:** الإيميل يوصل، واللينك يفتح صفحة كلمة مرور جديدة.
- [ ] **التسجيل بإيميل جديد:** إيميل التأكيد يوصل.
- [ ] **حجز من موبايل تاني على صفحة الحجز:** الحجز يظهر في الداشبورد من غير refresh، وجرس الإشعارات يرن.
- [ ] **تذكير بكرة من الموبايل:** واتساب يفتح على الرقم الصح، والرسالة فيها التاريخ والوقت.
- [ ] **خطة الزيارات:** اعمل خطة لعميل وتأكد إنها ظهرت. لو ظهرت خطط قديمة متكررة، دي من قبل التصليح، وتقدر تحذفها.
- [ ] **"مكتمل" على موعد له سعر** بعد تنفيذ `043`.
- [ ] **جدولة التذكير القديمة:** في Supabase افتح Database ثم Cron Jobs (أو `SELECT * FROM cron.job`). لو لقيت `send-whatsapp-reminders`، دي بتشغّل `send-reminders` كل نص ساعة من أيام Twilio. الكود بيبعت التذكير يدوي، فالأفضل توقفها (`SELECT cron.unschedule('send-whatsapp-reminders')`)، إلا لو Twilio لسه شغال عندك.
